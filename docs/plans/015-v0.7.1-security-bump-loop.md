# v0.7.1 security-bump loop

**Created:** 2026-05-10 (right after v0.7.0 tag)
**Branch:** `memex-v0.7` (continue; tag v0.7.1 from same branch)
**Purpose:** Close all 18 transitive vulnerabilities surfaced by `npm audit` after v0.7.0 ship. Designed to be executed as an iterative ralph-style loop with mechanical, testable steps.

## Context

`v0.7.0` shipped with 18 transitive vulns in the lockfile (all `fixAvailable: True` per `npm audit --json`):

| Severity | Count | Packages |
|---|---|---|
| **critical** | 2 | `openclaw`, `protobufjs` |
| **high** | 6 | `axios`, `basic-ftp`, `fast-uri`, `fast-xml-builder`, `path-to-regexp`, `picomatch` |
| **moderate** | 10 | `@anthropic-ai/sdk`, `@aws-sdk/xml-builder`, `@hono/node-server`, `brace-expansion`, `express-rate-limit`, `fast-xml-parser`, `follow-redirects`, `hono`, `ip-address`, `uuid` |

All vulnerable deps are **transitive** through three direct dependencies:
- `openclaw` (≥2026.3.22) — biggest umbrella; likely bringing hono/protobufjs/path-to-regexp/aws-sdk/express-rate-limit
- `openai` (≥6.21.0) — likely bringing axios/follow-redirects
- `@ofan/telemetry-relay-sdk` (≥0.2.1) — likely bringing some web stack

Direct deps in `memex/package.json` are clean. Memex's own code path doesn't touch axios/protobufjs/aws-sdk directly.

## Pre-decided judgment calls

- **Strategy order**: try `npm audit fix` (non-force) first, then bump the three umbrella deps to latest, then `overrides` in `package.json` as a last resort, **never** `npm audit fix --force` blind (140-package mutation per dry-run).
- **Branch**: stay on `memex-v0.7` (already tagged at v0.7.0); v0.7.1 tag will follow naturally.
- **Verification gate**: every dep change must pass `npm test` (725 tests) + `npm run build` before commit. Domain eval (`tests/domain-eval.ts`) skipped — no regression risk in dependency bumps unless API shape changes.
- **No code changes** unless an umbrella bump introduces a breaking API change that affects memex's call sites (then minimal patch + test).
- **No new features.** This is a pure security-bump release.

## Operating principle

Each item below is mechanically scoped: clear input (which deps to bump), clear output (vuln count drops), testable (npm audit + npm test). The loop's job is to close vulns; if a fix requires breaking-change handling, **stop and surface** rather than guess.

## Out of scope

- **Major version bumps** (e.g. `openclaw` 2026.x → hypothetical 2027.x with breaking changes). If the loop discovers an umbrella dep needs a major bump, **stop** and surface — that's a v0.8 conversation, not a security patch.
- **Switching dependencies** (e.g. ditching axios for fetch). Same reason.
- **Code refactors** beyond minimal call-site adjustments forced by an API rename.
- **`npm audit fix --force`** — explicitly forbidden. Dry-run shows 140-package mutation; that's a separate, deliberate decision.
- **CI workflow Node bumps** (Node 20 → 24 in actions) — separate concern, not security.
- **Branch operations**: don't merge to main, don't force-push, don't delete tags.

If an item the loop is working on *requires* an architectural decision to proceed, **stop and surface the question**.

## Loop operating rules

Each iteration:

1. **Read this file** to find the next unchecked `[ ]` item.
2. **Do that item.** One commit per item is preferred; one commit per logical group is acceptable.
3. **Verify** before claiming done:
   - `npm test` passes (725 tests baseline; surface immediately if count changes).
   - `npm run build` succeeds.
   - `git diff` looks like what was intended.
   - For SEC items: `npm audit` shows the expected vuln count drop.
   - Commit succeeds (don't bypass `--no-verify`; if pre-commit hook blocks, fix the underlying issue).
4. **Mark `[x]`** in this file in the same commit (or a follow-up commit) so the next iteration knows what's done.
5. **Push** to `origin/memex-v0.7`.
6. **End the iteration.** Don't try to do multiple items per iteration unless they're tightly coupled.

If an item is unclear or genuinely blocked:
- Mark it `[?]` with a one-line explanation.
- Surface in the iteration log below.
- Move on to the next item.

If all items are checked OR explicitly marked `[?]` with rationale, output:
```
<promise>V0.7.1 SECURITY BUMP COMPLETE</promise>
```

**Hard cap: 20 iterations.** If not done by then, surface the remaining vulns as user-decision items (e.g. "this needs a major version bump").
