The Players

Claude Code Built-in

Auto Memory + CLAUDE.md — zero config, every user has it
  • MEMORY.md — auto-maintained, 200 lines / 25KB cap
  • Topic files — overflow into debugging.md, api-conventions.md etc.
  • Auto Dream — background sub-agent consolidates after 24h + 5 sessions
  • No search — flat file loading, no semantic recall
  • Project-scoped — ~/.claude/projects/<project>/memory/

hermes-memory

Standalone MCP — pip install, zero infra, FTS5-only
  • Hot/cold tiers — 150 tokens injected always, unlimited cold storage
  • MEMORY_SPEC — typed facts: C[target] D[target] V[target], 65% compression
  • Scope lifecycle — auto-close after 6 idle turns, migrate to cold
  • Pressure relief — 70/85/95% triggers dedup → archive → consolidate
  • 7 MCP tools — write, search, tick, status, reflect, export, purge

mcp-memory-service

1,300 stars — 180+ releases, most mature option
  • Embeddings — sentence-transformers + SQLite-vec or ChromaDB
  • 24 MCP tools + REST API + HTTP dashboard
  • ~86% R@5 on LongMemEval with session storage
  • Heavy setup — Python, PyTorch optional, ~150MB minimum
  • Docker or pip — multiple install paths

agentmemory

736 stars — 2 months old, cross-agent focus
  • Triple-hybrid — BM25 + vector + knowledge graph fusion
  • 43 MCP tools, 12 auto-capture hooks, real-time viewer
  • One command — npx @agentmemory/agentmemory
  • Cross-agent — shared memory: Claude Code + Cursor + Gemini CLI
  • Young — API may shift, 5 contributors

Memex

Hybrid retrieval + autonomous dreaming — benchmark-validated quality
  • 94% E2E, 96% R@5 — highest retrieval quality (LongMemEval)
  • 3-phase dreaming — light + deep + LLM reflection (unique)
  • Hybrid retrieval — BM25 + vector + z-score fusion + reranking
  • 5 MCP tools — focused surface area
  • Dual platform — OpenClaw plugin + MCP server

Claude Code Memory Pain Points

Real problems from GitHub issues that memex can solve:

Silent truncation (#39811)

New entries appended past 200 lines are silently lost. No warning, no feedback. Users discover data loss after the fact.

Newest lost first (#40210)

Append-at-bottom + truncate-from-bottom means the most recent context is discarded while stale entries survive.

No semantic search

Flat file loading — Claude reads MEMORY.md top-to-bottom. No way to search by meaning. Irrelevant memories waste context.

No extension API

Can disable Auto Memory but can't extend it. No hooks, no custom storage backends, no programmatic access.

hermes-memory: Hot/Cold Architecture

Hot Tier (~150 tokens)

  • Always in context at session start
  • MEMORY_SPEC notation: D[auth]: JWT 7j
  • 65-78% compression vs prose
  • Typed: C=constraint, D=decision, V=value
Pressure triggers:
70% → merge duplicates
85% → archive closed scopes
95% → LLM consolidation
↔

Cold Tier (unlimited)

  • SQLite + FTS5, queried on demand
  • Max 20 results per search
  • Zero idle token cost
  • Scopes auto-migrate on close
Scope lifecycle:
Opens on first write
Closes: 6 idle turns, "merged"/"deployed"
Closed → cold automatically

Strategic Positioning

Core insight

hermes-memory is SQLite. Memex is PostgreSQL. One is zero-config and everywhere. The other is powerful and requires setup. Both have their market. Don't try to out-simple hermes-memory. Win on quality and intelligence.

What memex should do

Semantic recall

Claude's memory has no search. Memex has 94% E2E retrieval. The killer feature — find the right memory from thousands.

Autonomous dreaming

No competitor has offline consolidation. Learnings, contradiction detection, memory evolution. Unique differentiator.

Unlimited capacity

Claude's 200-line cap with silent truncation is a real pain point. Memex has no cap — store everything, find what matters.

Complement MEMORY.md

Use Claude's built-in for static project rules. Memex for dynamic knowledge that grows beyond 200 lines.

BM25-only default

hermes-memory proves FTS5-only is useful. Make BM25 the zero-config path. Embeddings as opt-in upgrade.

What memex should NOT do

Don't out-simple hermes

pip install hermes-memory is unbeatable for zero-config. Don't compete there.

Don't add 43 tools

agentmemory's 43 tools bloat context. Keep the 5-tool surface area focused.

Don't build a dashboard

Stay focused on memory quality. Dashboards and REST APIs are distractions.

Don't replace CLAUDE.md

It's version-controlled and team-shared. Memex is dynamic and personal. Different jobs.

Open Product Questions

  1. Should memex generate a memories.md file that Claude's Auto Dream can discover and incorporate? Complement rather than compete.
  2. Should the hot/cold tier pattern be adopted? Small injected summary (~150 tokens) + deep recall on demand. Currently memex injects full text.
  3. Should BM25-only be the default with embeddings as opt-in? Zero-config for basic use, full power for users with infrastructure.
  4. Per-project or global? Claude Code is project-scoped. Memex is currently global. Should it match Claude's model?
  5. Write-time contradiction detection — lightweight cosine check on store(), or keep it batch-only in dreaming?
